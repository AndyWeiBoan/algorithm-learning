# 看題線索表（題目特徵 → 招式）

> 2026-11-16 建立。起因：853、503 用到的技巧都學過，卡在「看到題目想不起要用哪個」。
> `insight-日誌.md` 是「招式 → 細節」，這份反過來：**從題目的字面特徵查到招式**。
>
> **用法**：沒看過的題，讀完題目先花 2 分鐘逐條比對下面的「看到」欄，圈出命中的，再開始想。
> **維護**：每次卡住，問「題目哪個字應該讓我想到這招？」補一條進來（寫在對應區塊，附上卡住的題號）。

## 先問這 6 句（每題讀完照順序問）

| # | 問自己 | 答案 → 方向 |
|---|---|---|
| 1 | **打亂輸入，答案會變嗎？** | 不變 → 可以排序／照有意義的鍵排（853 照 position、15、56）；會變 → 保持原順序（739、496、503） |
| 2 | **暴力的內層迴圈在找什麼？** | 某個值在不在 → hash；往右第一個更大／更小 → 單調 stack；在已排序資料裡找 → 二分或雙指針 |
| 3 | **要「連續一段」還是「任意挑幾個」？** | 連續 → 滑動窗口或前綴和；任意挑 → 排序加雙指針、回溯或 DP |
| 4 | **要「全部列出來」還是「數量／最好的值」？** | 全部列出 → 回溯；數量或最好的值 → DP 或貪心 |
| 5 | **能不能拆成更小的同型問題？** | 能 → 遞迴（樹）或 DP，先想「最後一步」 |
| 6 | **東西之間有「相連、依賴、最短」嗎？** | 有 → 圖：BFS 求最短，DFS 求連通，拓撲處理依賴 |

例：853 → 第 1 句打亂不變 → 照 position 排；第 2 句暴力是每台往前看會不會被擋，找的是「前面的車隊頭」→ stack。
