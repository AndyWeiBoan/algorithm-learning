### 滑動視窗 Sliding Window
- **固定視窗 = 「吃一個、吐一個，長度不變」**。右邊進 `s[i]`，視窗滿了（`i >= 視窗長`）就吐掉 `s[i - 視窗長]`，不需要 while、不需要 head 指針管理。
- **可變視窗 = 「擴到不合法才縮」**。求最長：擴到違規縮一步；求最短（76）：擴到覆蓋再拚命縮。
- **count 計數技巧**：用一個 count 記「還差幾個」，O(1) 判斷視窗是否達標，比每次比 26 格陣列省。
- **先改狀態，再判斷**：吃 → 先 `dict[c]--` 再看是否補上缺口（`>= 0` → `count--`）；吐 → 先 `dict[left]++` 再看是否變缺（`> 0` → `count++`）。兩邊是鏡像。
- **負數記錄「多餘」**：讓 dict 可以變負，多塞的字元用負值記住，吐出去時才不會誤判 count。
- **stale maxFreq 不影響答案**（424）：窗口「只增不縮」地往右滑，maxFreq 過時偏大也不會記到假的更大窗口。
- **同一張卡的家族**：209 / 3 / 1004 / 904 / 438 / 567 / 424 / 76 全是「窗口最多容忍 k 個例外，求最長/最短合法窗口」，換的只是「例外」定義與窗口固不固定。

### 鏈結串列 Linked List
- **所有特例的根源 = head 是唯一沒有「前一個節點」的節點**。刪/接都需要抓「目標的前一個」，唯獨 head 沒有 → 才需要特判。
- **dummy node = 幫 head 補一個前一個**，補完開頭跟中間長一樣，特判消失。觸發訊號：「我需要 X 的前一個，而 X 可能是 head」→ 加 dummy。回傳 `dummy.next`（不是 dummy）。通用於 19 / 24 / 21 / 203。
- **單向鏈表刪節點 = 抓著它的前一個**，`slow.next = slow.next.next`。所以雙指針要讓 slow 停在「目標的前一個」，不是停在目標身上。
- **雙指針間距（19）**：fast 先走 n 步拉開 gap=n，再一起走到 fast 到底，slow 剛好停在倒數第 n 個的前一個。去頭時迴圈跑 0 次、slow 留在 dummy —— 那是迴圈正常運作，不是特例。
- **遞迴鏈表（206/24）**：每層回傳「處理完那段的新頭」，本層只接線、信任下層。別想著回傳「有沒有翻轉過」之類的旗標。
- **快慢指針起點相等的坑（142）**：slow/fast 同從 head 時，不能「先比較再移動」（一進迴圈就誤判相遇），要**先各走一步再比較**（do-while 形狀）。
- **Floyd 找環入口（142，記結論型）**：偵測到相遇後，一根留相遇點、一根回 head，**同速各走一步，相撞點 = 入口**。原理 `a = k·c − b`（a=head→入口，b=入口→相遇點，c=環長；fast 走 2 倍 slow 推得）→「相遇點往前繞回入口」的距離剛好等於 a。推不出來是正常的，記結論、信證明即可；面試 HashSet O(n) 空間版也完全可接受。

### 二元樹 Binary Tree
- **三種 DFS 遍歷,遞迴版只差「Add 根」那行的位置**：前序在最前、中序在中間、後序在最後;左右遞迴的順序不變。
- **中序迭代(通用骨架)**：單層 while,條件 `stack 非空 || current != null`。`current` 一路往左 push 下沉;左盡則 pop 處理、轉右子樹。前序也能套這骨架(處理時機改在 push 當下)。
- **後序迭代(反轉 trick)**：照前序迭代骨架,但 push 順序改「**先左後右**」→ 收集順序變「根→右→左」→ **最後 `res.Reverse()`** → 左右根。⚠️ push 順序:想讓「右」先 pop,右要**最後**推(stack 後進先出),所以是先 push left、後 push right。
- **空樹邊界**：迭代版若一開頭 `stack.Push(root)`,務必先 `if (root == null) return ...`,否則 pop 出 null 點 `.val` 會 NPE。
- **自底向上聚合（110/543/124/337 同骨架）**：後序遞迴**回傳一個值(高度)給父親**,同時用**外部變數累積答案**(110 用 -1 哨兵判平衡;543 用 max 追蹤「左高+右高」)。鐵則:**要往上傳的(高度)跟要的答案(直徑)是兩個不同的東西 —— 答案擺外面、別跟著回傳上去**。最後回傳的是外部那個累積變數,不是遞迴的回傳值。
- **驗 BST(98)**：合法 BST 的**中序是嚴格遞增** → 中序跑一遍、後一個必須 `>` 前一個。比範圍法乾淨,還躲掉 int 極值當哨兵的坑。
- **層序 BFS（102，通用模板)**：用 **queue** 不是 stack。每輪迴圈**先把 `count = queue.Count` 存起來鎖住「當層節點數」**,for 跑 count 次收完整層、把孩子入列,**整層收完才 `res.Add(該層)`**(別在內層迴圈裡 Add，會把同層重複加)。這個「先記 count」手法 → 右視圖 / 鋸齒層序 / 各層最大值 都套得上。
- **102 也能 DFS**：遞迴多帶一個 `level` 參數,`result.Count < level` 代表第一次踏到新層 → 建新 list;否則 `result[level-1].Add(val)`。關鍵是「層 = 遞迴深度」。
- **102 家族（同模板改幾行，要時再做不必逐題排）**：107 由下往上(反轉)、199 右視圖(每層最後一個)、513 最左下(最後層第一個)、515/637 每層 max/avg、103 鋸齒(偶數層反轉)、116/117 連 next、111 最小深度(BFS 遇葉即停)。
- **🔑 深議題:層序 BFS 的「count 鎖層」= 無權圖最短路引擎**。開 §12 圖論時直接複用同一套(孩子入列 → 鄰居入列 + visited):島嶼 200、腐爛橘子 994(多源 BFS)、Word Ladder 127(最短路)、課程表 207(拓撲/Kahn)。樹層序只是圖 BFS 最乾淨的特例。

- **LCA 236 的提早回傳（最不直覺的一點）**：碰到 `p` 或 `q` 就 `return root`，**不往下找**。兩種情況都成立 —— ① `q` 不在 `p` 底下 → 往上傳 `p`，真正的 LCA 在更上面那個「left、right 都非 null」的節點；② `q` 在 `p` 底下 → `p` 自己就是 LCA，提早回傳正好是答案。題目那句「節點可以是自己的祖先」不是廢話，它正是這個提早回傳能成立的理由。
- **🩸 236 踩到的，是 insight 日誌裡那條 DP 慣性錯的同一類**：第一版拿 `root.left` / `root.right`（**原始子節點**）去比對 p/q，而不是用 `LowestCommonAncestor(root.left,…)` 的**回傳值**。compose 的永遠是「子問題的答案」，不是原始輸入。DP 寫成 `nums[i-2]`、樹寫成 `root.left`，是同一個手滑。
- **「直接子節點」不等於「子樹裡有」**：`root.left == p` 只檢查到一層；p 可能埋在更深處。而且 `p`/`q` 對稱，沒有誰一定在左邊。
- **🔑 236 真正的卡點（使用者自己的診斷）：「問題是我想太多去判斷」。** v2→v3 是**純刪除** —— 砍掉「直接小孩是不是 p/q」「左右對稱配對」這些手寫特例，核心一行沒動，六行就全對。
  這就是鏈結串列那條「**信任下層**」在樹上的版本：本層只問「左、右各回傳了什麼」，剩下的交給遞迴。會想手動列特例，代表還沒信任遞迴。
  → **遞迴題的自查**：我是不是在列舉特例？能不能刪掉？刪到只剩「base case + 左右回傳 + 怎麼合併」三件事。

### 二分搜尋 Binary Search
- **精髓不是「找某個數」,是「找一道是非題的翻面線」**。把問題變成「隨索引由 false 單調翻成 true 的條件」(如「這格 > target 嗎?」),二分逼近那條翻面線。停在 `left > right`(且 `left == right+1`)時,**left = 第一個 true、right = 最後一個 false**——意義是寫死可預測的,要哪個看你問什麼,不用猜。這一句同時解 34/35 甚至 33/69/875(對答案二分,那些根本沒 target 可比,但都有條件翻面線)。
- **邊界三問(我的弱點,寫二分先自問)**:① `right` 初值 `Length-1` 還 `Length`?② `while` 是 `<` 還 `<=`?③ 沒中時 `mid+1`/`mid-1` 怎麼移?704/34/35 我用的是 `right=Len-1` + `left<=right` + `mid±1` 這套(交錯式)。
- **🔑 一個決策定生死:「mid 留不留」**(153 磨出來、我最弱的一環)。看迴圈有沒有分支**留著 mid**(`right=mid`,沒 ±1):**全丟 mid → `left<=right` + `mid±1`**(704/34/35);**留 mid → `left<right` + `right=mid`**(153 收斂式)。這不是喜好是**終止性**:`right=mid` 配 `<=` 會在剩一格時原地打轉→無窮迴圈(33 卡死 33 萬次同源);全 `mid±1` 配 `<` 會漏掉最後一格。**「mid 留不留」同時定了 `<`/`<=` 和移動方式**——抓這一個決策,邊界全清。
- **二分只有三形狀**:① 找特定值(命中 return,704) ② 找邊界/插入點(lower/upper bound,34/35) ③ 收斂到答案(mid 可能是答案要留,153)。第 ③ 種:min 就是收斂目標本身,別像我當時用 idx 硬追(繞)。缺的是三形狀的間隔閉卷重練,不是題量。對答案二分(875/69)是唯一非換皮的新形狀。
- **邊界二分的收尾守衛(34 磨三版的坑)**：兩支 lower/upper bound 回傳值**可能越界**(空陣列、target 比全部大 → 回 `Length`)。取 `nums[idx]` 前必須先擋:`idx<0 || idx>Len-1 || nums[idx]!=target → 回無解`。**用 `||` 讓「越界」直接觸發無解**(不是 `&&` 把越界排除掉),且 C# `||` 短路會擋住越界取值、順帶防崩。找插入點=找左邊界=同一支(35 就是 34 的 FindLeft)。

### 動態規劃 DP
- **🔑 寫轉移方程的萬能鑰匙:「盯最後一個決定」**。要 `dp[i]`,就問「最後一步/最後一塊有哪些可能?」——每個可能都吃掉一部分、留下一個更小的子問題(某個 dp[j])。列完所有可能:**數幾種→相加**、**求最好→min/max**。這一招統一了所有做過的:70 最後一步 1 或 2 階(dp[i-1]+dp[i-2])、198 最後一間偷不偷(max)、322 最後一枚硬幣哪個(min(dp[i-c]+1))、64 最後一步從上或左(min)、91 最後一塊切 1 或 2 位(dp[i-1]+dp[i-2] 各帶合法檢查)、53 最後一個數接前面或重開(max)。方程不是靈感,是被這個問題逼出來的。
- **🩸 我的慣性錯:方程裡把「子問題答案 dp[…]」寫成「原始輸入 nums/grid[…]」**。198 寫成 nums[i-2](該 dp[i-2])、64 寫成 grid[i-1][j](該 dp)、91 寫成 s[i]（該 dp）。compose 的永遠是**已算好的 dp**,不是單格原始值。
- **狀態要先定義精準再寫方程**:`dp[i]` 是「前 i 個」還是「以 i 結尾」?53 是「以 i 結尾的最大和」→ 所以答案要取**所有 dp 的 max**,不是 dp[n-1](最大段可在任意處結尾)。定義含糊 → 方程和收尾都會歪。
- **能否 O(1) 滾動 = 看回看距離固定否**:70/198/746/213 只看前 1~2 格 → 留兩變數即可;322 的 dp[i-c] 距離=面額可任意遠 → 省不掉整張表。
- **0/1 vs 完全背包(416 vs 322)**:每個東西只能用一次(0/1)→ 外圈物品、內圈容量**由大到小**;可無限用(完全)→ 內圈由小到大。方向錯會把同一個東西重複用。← 最反直覺、待重練。
- **我自證的一刻(53)**:自設「挑新題證明我寫不出方程」的測試,結果閉卷把核心方程推對、還自己避開 dp[n-1] 的坑。→ 弱點是「還沒練熟」不是「沒天份」;閉卷解新題才是真證據,累到底時的自我判決不算數。

### 圖論 Graph
- **島嶼類模板(200/695/130/994)**：外層 for/for 掃全圖找起點,遇到「未訪問的陸地」→ 島數 +1,再用 DFS/BFS 把整塊連通陸地標記(改成 '2' 或 visited)。相連只算上下左右。
- **🩸 血淚教訓(200 磨了三天的坑)**：**「掃描」和「flood fill」必須用不同的座標變數**。外層迴圈的 `i/j` 只歸掃描管;BFS/DFS 一定要用自己的區域變數(`a/b`),絕不能在 flood 裡改寫 `i/j`。一旦讓 flood 借用掃描的計數器,掃描位置被劫持 → 中間的島被跳過 → 系統性少算。這是「指針/座標操作」弱點的典型現形。
- **flood fill 家族一條龍(200→695→130→417)**：換出發點、換走的條件、換收尾,引擎不變。200 數塊、695 回傳面積取 max、130 從**邊界**flood 反推(補集)、417 **兩海各 flood 一次取交集**(兩張 bool 表兼 visited,不需去重)。判斷可否就地改矩陣:值域有限有安全 sentinel → 就地省空間;任意值/需多種標記(417)→ 開獨立 visited。
- **多源 BFS(994 腐爛橘子)兩個必踩坑**：① **count 鎖層** —— 層數迴圈先 `var count = queue.Count` snapshot,不能在 `for` 條件裡即時讀 `queue.Count`(邊 enqueue/dequeue 邊讀會錯)。② **入隊即標記** —— visited 要在 `Enqueue` 當下標,不是 `Dequeue` 才標,否則同格在排隊空窗被鄰居重複入隊 → 多出幽靈層 → 分鐘數多算。收尾:還有新鮮橘子回 -1、一開始就沒新鮮回 0。
- **拓撲排序 / Kahn(207 課程表)一句種子**:**「入度 0 先修,修掉就幫後續 -1,新歸 0 再進隊;收尾還有入度>0 = 有環。」** 記住「入度」+「一層層剝」兩個詞就能當場重推整套。實作:入度陣列(下標=課、值=入度)+ 鄰接表 `Dict<int,List<int>>`(課→後續清單,只建一次別每輪重掃,否則退化 O(點×邊))。踩坑:`dict[缺key]` 在 C# 會丟 `KeyNotFoundException` —— 葉子課(沒後續)很正常會被 dequeue 到,取清單前先 `ContainsKey` 擋掉。DFS 三色找環是第二種手法,同 O(點+邊),不更優。

### 回溯 Backtracking
- **聖三一骨架(77 首題,整章共用)**:`for i from idx: 選 subsets.Add(i) → 遞 backtrack(i+1) → 撤 subsets.RemoveAt(last)`。base case 滿足條件就收集後 return。「回溯」之名來自那個**撤銷**動作:離開一格前把腳印擦掉,還原現場給兄弟分支。
- **三顆可調旋鈕**(換題只轉這三顆):① **base case**(何時收集:湊滿 k / 和==target / 走到字串尾)② **for 起點**(`i+1`=組合不重排、`idx`=可重複用、`0`+visited=排列)③ **剪枝**(選之前先判值不值得,骨架穩了再加)。
- **兩個血坑**:① 收集時必須 `results.Add(new List<int>(subsets))` 拍**快照** —— subsets 全程同一物件一直被改,直接 Add 它本身會讓所有答案最後變同一個殘骸(通常全空)。② `RemoveAt` 不能漏 —— 漏了路徑會越黏越長,兄弟分支被污染。
- **要不要遞迴?** 77 這種規律組合其實可不遞迴(BFS 一層層長=我最初的 queue 直覺,對但空間膨脹到 O(答案數);或里程表遞增下標,超省但只對純組合有效)。但**整章預設遞迴**:決策樹深度不定、需要乾淨的狀態回退,遞迴用呼叫堆疊免費幫你管這兩件事。學回溯的重點=把這副遞迴骨架練成反射。
- **🩸 哨兵值撞真實資料(79 自己抓到的)**:用「就地改盤面」當 visited 時,標記值**必須是資料域裡不可能出現的**。79 盤面是字母,我拿 `'x'` 當走過標記,但盤面本來就有真的 `'x'`(word 還要踩它)→ `board==’x’` 分不清標記與真值 → 漏答案。改成非字母 `'-'` 解決。**推廣**:in-place sentinel 前先問「這個值原始資料會不會出現?」會就換、或改用獨立 visited 結構。連帶教訓——**fuzz 的輸入域要涵蓋你當哨兵的那個值**,否則測不到這類撞值(我第一輪字母只用 a~d 就漏了)。
- **「可以放」≠「一定放」(22 括號生成悟到的)**:回溯每一步的條件是**許可**不是命令。左括號能放(`left>0`)、右括號也能放(`left<right`)時,**兩條分支都要走**——不是「比大小挑一個放」。`()()` 和 `(())` 就是同一步「兩個都許可」時分岔出的不同結果。當題目不是「for 跑候選陣列」而是「每步幾個離散選擇」,就手寫多個 if、各判各的許可條件、能放就開分支。收集只在完整狀態(`left==0&&right==0`)。
- **🩸 狀態還原是我的真弱點(39 磨出來的根本原理)**:回溯的核心不變量 = **每次回到上一層,狀態要跟「往下走之前」一模一樣**。而還原方式取決於怎麼傳:**傳值的(int sum)自動還原免手動;傳參考的(List subsets)共用同一物件,改了就得自己 RemoveAt 撤回**。→ 早上鬼打牆想「回傳 sum、刷新 sum」是白工,因為 sum 傳值本來就沒被父層動到;只有 subsets 這種共用參考才非撤不可。**判準一句話:往下傳的東西,傳值的自動還原、傳參考的要自己還原,離開這層前確認每個共用參考都退回進來時的樣子。** 操作上更防呆:`Add`/`RemoveAt` 當成一對括號夾住遞迴,中間別 `return`(剪枝的跳出移到 Add 之前、==target 只記錄不 return),全層只留一個 RemoveAt、一個離開點,就沒有「這裡要不要撤」的判斷題。
